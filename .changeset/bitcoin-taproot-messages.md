Taproot accounts and message signing. `deriveAccount({chain: 'bitcoin', addressType: 'p2tr'})` is a BIP-86 account at `m/86'/{coin}'/{account}'/{change}/{index}` with a Bech32m address, its key tweaked inside the engine; P2WPKH stays the default, and `{path}` alone is still P2WPKH. `watchAccount` and `addressFromPublicKey` take `addressType: 'p2tr'` too (an x-only key or SEC1). Taproot accounts plan payments at 57.5 vB an input and sign them over BIP-341 with SIGHASH_DEFAULT. PSBTs gain BIP-371's fields: Taproot accounts write `PSBT_IN_TAP_INTERNAL_KEY` and `PSBT_IN_TAP_BIP32_DERIVATION` (and the output ones on change) and sign `PSBT_IN_TAP_KEY_SIG`, also for a coin of their key under a script tree whose `PSBT_IN_TAP_MERKLE_ROOT` is given; `decodePsbt` reports them (`taprootInternalKey`, `taprootMerkleRoot`, `taprootDerivations`, `taprootKeySignature`); and `finalizePsbt` finalizes P2WPKH and Taproot key path inputs together, from any accounts, verifying every signature on the engine, including inputs a signer already finalized, which it used to refuse. Accounts gain `signMessage({message, format?})` (BIP-322 simple, prefixed `smp` by default, `bip322-unprefixed`, or `legacy` BIP-137 for P2WPKH) and `verifyMessage`, and the chain `verifyMessage({address, message, signature})`, which also reads legacy signatures for P2PKH and P2SH-P2WPKH and says `UNSUPPORTED` for what needs a script interpreter. `features.messageSigning` and `features.taproot` are now true, and `formats` lists `bech32m-p2tr`, `p2tr-bip341`, `bip322-simple` and `bip137`. Taproot needs an engine with `secp256k1-schnorr` and `taproot-tweak`, which the adapter does not require: on an engine without them it registers, P2WPKH works, and Taproot throws `UNSUPPORTED`. Held to BIP-86's and BIP-341's vectors, every BIP-322 vector, Bitcoin Core's message vector, `@scure/btc-signer` (sighashes of every type, transactions and PSBTs byte for byte) and `@noble/curves`.

Type changes to check when upgrading: `BitcoinWatchAccount.addressType` is now `'p2wpkh' | 'p2tr'` (it was `'p2wpkh'`), so code that assumed P2WPKH should narrow on it; `BitcoinPsbtInput` and `BitcoinPsbtOutput` have the new Taproot fields, which code building those objects itself must add.
